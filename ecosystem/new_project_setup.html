🚀 New Project Setup

"Yes, all of this is GUI-only. No, Apple still hasn't given us a CLI. Deep breaths."

Adding a new app to the Gwen Widgets ecosystem. Part A is Xcode GUI work (human). Part B is verification, code & config (Claude).

✅Before You Start

  • Xcode 16+ with iOS 18+ and watchOS 11+ SDKs
  • Repository cloned at /Users/haslo/projects/health_widgets/
  • Apple Developer account with team ID 9SXAEFW8AN

🧑‍💻Part A: Xcode Setup

Human
1
Create Xcode Project

File → New → Project → iOS → App

Product Name: NewApp, Org: com.cybergwen, SwiftUI, Swift, No storage. Save to /Users/haslo/projects/health_widgets/.

2
Create Widget Extension

File → New → Target → Widget Extension — Name: NewAppWidgets

Widget entitlements go at project root (NewApp/NewAppWidgetsExtension.entitlements).

3
Create Watch App (optional)

File → New → Target → watchOS → App — Name: NewAppWatch Watch App, SwiftUI.

4
Add HealthWidgetsCore Package

Select project → Package Dependencies → + → Add Local... → Packages/HealthWidgetsCore. Link to ALL targets: General → Frameworks → + → HealthWidgetsCore on each.

5
Add Capabilities to All Targets

On every target (app, widget, watch): Signing & Capabilities → + Capability

  • App Groups → group.com.cybergwen.HealthWidgets
  • HealthKit
6
Test Targets

Auto-created by Xcode. App integration tests go in NewApp/NewAppTests/; package unit tests stay at Packages/HealthWidgetsCore/Tests/.

7
Add to Workspace

Open HealthWidgets.xcworkspace, then: File → Add Files to "HealthWidgets" → select NewApp/NewApp.xcodeproj.

🤖Part B: Verification, Code & Config

Claude
1
Verify Project Structure

Mirrors A.1–3. Check NewApp/NewApp.xcodeproj exists and contains expected targets (app, widget, watch).

2
Verify Package Linking

Mirrors A.4. Confirm HealthWidgetsCore is linked to ALL targets (app, widget, watch) in the pbxproj.

3
Verify Capabilities & Entitlements

Mirrors A.5. For each target, check entitlements contain:

  • com.apple.developer.healthkit = true
  • com.apple.security.application-groups includes group.com.cybergwen.HealthWidgets

Widget entitlements must be at project root (NewApp/NewAppWidgetsExtension.entitlements), not nested. Widget Info.plist must contain com.apple.widgetkit-extension extension point.

4
Verify Workspace

Mirrors A.7. Confirm HealthWidgets.xcworkspace/contents.xcworkspacedata includes group:NewApp/NewApp.xcodeproj.

5
Replace Entry Points with configure()

Replace Xcode’s auto-generated boilerplate in each @main struct. Every process must call HealthWidgetsCore.configure() in init().

Main App — NewApp/NewApp/NewAppApp.swift

import SwiftUI
import HealthWidgetsCore

@main
struct NewAppApp: App {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp"
        ))
    }
    var body: some Scene {
        WindowGroup { ContentView() }
    }
}

Widget Extension — NewApp/NewAppWidgets/NewAppWidgetsBundle.swift

import SwiftUI
import WidgetKit
import HealthWidgetsCore

@main
struct NewAppWidgetsBundle: WidgetBundle {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp.Widgets"
        ))
    }
    var body: some Widget {
        // Add widgets here
    }
}

Watch App — NewApp/NewAppWatch Watch App/NewAppWatchApp.swift

import SwiftUI
import HealthWidgetsCore

@main
struct NewAppWatchApp: App {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp.Watch"
        ))
    }
    var body: some Scene {
        WindowGroup { ContentView() }
    }
}
Missing configure() = Fatal Crash

Each process runs independently. Missing configure() = crash on app group / logger access.

6
Add Storage Keys (if needed)

Only if the app uses AppDataStorage. Add a nested enum to StorageConfiguration.Key:

public enum NewApp {
    public static let someData = "appdata.newapp.somedata"
}
7
Update Documentation
  • docs/ecosystem/index.html — Add app card
  • docs/llm_context/architecture.md — Services, models, file tree
  • CLAUDE.md — Build commands, service listings
  • docs/newapp/ — Concept docs if needed
8
Verify Builds
# iOS app
cd /Users/haslo/projects/health_widgets/NewApp && \
  xcodebuild -scheme NewApp -destination 'platform=iOS Simulator,name=iPhone 17' build

# watchOS app
cd /Users/haslo/projects/health_widgets/NewApp && \
  xcodebuild -scheme 'NewAppWatch Watch App' \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' build

# Package tests (unchanged)
cd /Users/haslo/projects/health_widgets/Packages/HealthWidgetsCore && \
  xcodebuild test -scheme HealthWidgetsCore -destination 'platform=iOS Simulator,name=iPhone 17'
Build Directory Matters

Run xcodebuild from NewApp/, not the project root. The root’s SPM workspace confuses scheme resolution.

⚠️Common Pitfalls

SymptomCauseFix
Fatal crash on widget launch Missing configure() in widget init() Add HealthWidgetsCore.configure()
Widget shows stale/no data Wrong or missing App Group Verify group.com.cybergwen.HealthWidgets on all targets
“does not contain a scheme” Running xcodebuild from project root cd into NewApp/ first
Widget entitlements not found Entitlements nested in widget folder Move to project root, update CODE_SIGN_ENTITLEMENTS
Info.plist compiled as source Missing file sync exception Exclude Info.plist from build phase membership
Watch build: wrong device family TARGETED_DEVICE_FAMILY not 4 Check build settings for watch targets
