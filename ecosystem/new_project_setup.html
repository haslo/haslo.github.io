🚀 New Project Setup

"Yes, all of this is GUI-only. No, Apple still hasn't given us a CLI. Deep breaths."

A step-by-step guide for adding a new app to the Gwen Widgets ecosystem. Steps 1–6 are Xcode GUI work. Steps 7–10 are LLM-automatable. Step 11 verifies everything builds.

✅Before You Start

  • Xcode 16+ installed with iOS 18+ and watchOS 11+ SDKs
  • Repository cloned at /Users/haslo/projects/health_widgets/
  • Apple Developer account with team ID 9SXAEFW8AN
  • Inner peace with the fact that Xcode project creation is GUI-only
1
Create Xcode Project
GUI — Xcode only

File → New → Project → iOS → App

  • Product Name: NewApp
  • Organization Identifier: com.cybergwen
  • Interface: SwiftUI
  • Language: Swift
  • Storage: None
  • Save location: /Users/haslo/projects/health_widgets/

This creates NewApp/NewApp.xcodeproj and NewApp/NewApp/.

Auto File Discovery

Xcode uses PBXFileSystemSynchronizedRootGroup — new Swift files added to NewApp/NewApp/ are automatically picked up by the build. No pbxproj edits needed.

2
Add HealthWidgetsCore SPM Package
GUI — Xcode only

Select the project (blue icon) in the navigator, then:

Package Dependencies tab → + → Add Local...

  • Navigate to Packages/HealthWidgetsCore (relative path: ../Packages/HealthWidgetsCore)
  • When prompted, select the NewApp target
Widget & Watch Targets

You must also link HealthWidgetsCore to the widget extension and watch app targets later. For each target: General → Frameworks, Libraries, and Embedded Content → + and select HealthWidgetsCore.

3
Add App Group + HealthKit Capabilities
GUI — Xcode only

Select the NewApp target, then:

Signing & Capabilities → + Capability → App Groups

  • Add: group.com.cybergwen.HealthWidgets

Then add HealthKit:

+ Capability → HealthKit

The resulting entitlements file should contain:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.developer.healthkit</key>
    <true/>
    <key>com.apple.security.application-groups</key>
    <array>
        <string>group.com.cybergwen.HealthWidgets</string>
    </array>
</dict>
</plist>
Same App Group Everywhere

Use the exact same app group (group.com.cybergwen.HealthWidgets) on ALL targets — app, widget extension, watch app. The cache and persistent storage depend on it.

4
Create Widget Extension Target
GUI — Xcode only

File → New → Target → Widget Extension

  • Product Name: NewAppWidgets

Then configure the new target:

  • Add App Groups capability with group.com.cybergwen.HealthWidgets
  • Add HealthKit capability
  • Link HealthWidgetsCore via General → Frameworks

Verify the widget Info.plist contains:

<key>NSExtension</key>
<dict>
    <key>NSExtensionPointIdentifier</key>
    <string>com.apple.widgetkit-extension</string>
</dict>
Entitlements Location

The widget entitlements file goes at the project root (e.g., NewApp/NewAppWidgetsExtension.entitlements), not nested inside the widget folder. If builds fail with entitlements errors, check CODE_SIGN_ENTITLEMENTS in build settings.

Info.plist

The widget Info.plist should be excluded from file sync automatically. If you see build errors about Info.plist being compiled as source, verify its build phase membership.

5
Create Watch App Target
GUI — Xcode only (optional)

File → New → Target → watchOS → App

  • Product Name: NewAppWatch Watch App
  • Interface: SwiftUI

Then configure:

  • Add App Groups capability with group.com.cybergwen.HealthWidgets
  • Add HealthKit capability
  • Link HealthWidgetsCore via General → Frameworks
Device Family

TARGETED_DEVICE_FAMILY = 4 should be set automatically for watch targets. If the watch build fails, verify this in the target's build settings.

6
Test Targets
Mostly automatic

Xcode auto-creates NewAppTests and NewAppUITests targets when you create the project. Watch test targets are also created with the watch app.

  • Bundle ID pattern: com.cybergwen.NewAppTests, com.cybergwen.NewAppUITests
  • Package unit tests stay at Packages/HealthWidgetsCore/Tests/
  • App-specific integration tests go in NewApp/NewAppTests/

🤖What Claude Can Do

Steps 1–6 above require the Xcode GUI. Once those are done, steps 7–11 below are fully automatable. Here’s a prompt you can paste:

Copy-Paste Prompt

“I’ve created NewApp in Xcode with widget and watch targets and added capabilities. Please write the entry points with configure(), add it to the workspace, and verify builds.”

7
Write Entry Points with configure()
LLM-automatable

Every process (app, widget extension, watch app) must call HealthWidgetsCore.configure() in its @main struct's init().

Main App — NewApp/NewApp/NewAppApp.swift

import SwiftUI
import HealthWidgetsCore

@main
struct NewAppApp: App {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp"
        ))
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

Widget Extension — NewApp/NewAppWidgets/NewAppWidgetsBundle.swift

import SwiftUI
import WidgetKit
import HealthWidgetsCore

@main
struct NewAppWidgetsBundle: WidgetBundle {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp.Widgets"
        ))
    }

    var body: some Widget {
        // Add widgets here
    }
}

Watch App — NewApp/NewAppWatch Watch App/NewAppWatchApp.swift

import SwiftUI
import HealthWidgetsCore

@main
struct NewAppWatchApp: App {
    init() {
        HealthWidgetsCore.configure(.init(
            appGroupID: "group.com.cybergwen.HealthWidgets",
            loggerSubsystem: "com.cybergwen.NewApp.Watch"
        ))
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
Missing configure() = Fatal Crash

Each process (app, widget, watch) runs independently. If ANY of them is missing the configure() call, it will crash at runtime when accessing the app group container or logger.

8
Add to Workspace
LLM-automatable

Edit HealthWidgets.xcworkspace/contents.xcworkspacedata to include the new project.

Before

<?xml version="1.0" encoding="UTF-8"?>
<Workspace version = "1.0">
   <FileRef location = "group:OmniWidget/OmniWidget.xcodeproj"></FileRef>
   <FileRef location = "group:Pipi/Pipi.xcodeproj"></FileRef>
</Workspace>

After

<?xml version="1.0" encoding="UTF-8"?>
<Workspace version = "1.0">
   <FileRef location = "group:OmniWidget/OmniWidget.xcodeproj"></FileRef>
   <FileRef location = "group:Pipi/Pipi.xcodeproj"></FileRef>
   <FileRef location = "group:NewApp/NewApp.xcodeproj"></FileRef>
</Workspace>
9
Add Storage Keys
LLM-automatable (if needed)

Only needed if the app uses AppDataStorage for source-of-truth data (like Pipi uses for pee logs and pattern profiles).

Add a nested enum to StorageConfiguration.Key in Packages/HealthWidgetsCore/Sources/HealthWidgetsCore/Services/Storage/StorageConfiguration.swift: 

public enum Key {
    public enum Pipi {
        public static let peeLog = "appdata.pipi.peelog"
        // ...
    }

    // Add for new app:
    public enum NewApp {
        public static let someData = "appdata.newapp.somedata"
    }
}

11
Verify Builds
LLM-automatable
# iOS app
cd /Users/haslo/projects/health_widgets/NewApp && \
  xcodebuild -scheme NewApp \
  -destination 'platform=iOS Simulator,name=iPhone 17' build

# watchOS app
cd /Users/haslo/projects/health_widgets/NewApp && \
  xcodebuild -scheme 'NewAppWatch Watch App' \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' build

# Package tests (unchanged)
cd /Users/haslo/projects/health_widgets/Packages/HealthWidgetsCore && \
  xcodebuild test -scheme HealthWidgetsCore \
  -destination 'platform=iOS Simulator,name=iPhone 17'
Build Directory Matters

You MUST run xcodebuild from the app’s directory (e.g., cd NewApp/), not the project root. The project root contains the SPM workspace which confuses xcodebuild into looking for the wrong scheme.

⚠️Common Pitfalls

SymptomCauseFix
Fatal crash on widget launch Missing configure() in widget bundle init() Add HealthWidgetsCore.configure()
Widget shows stale/no data Wrong or missing App Group Verify group.com.cybergwen.HealthWidgets on all targets
“does not contain a scheme named NewApp” Running xcodebuild from project root cd into NewApp/ directory first
Widget entitlements not found Entitlements nested in widget folder Move to project root, update CODE_SIGN_ENTITLEMENTS
Info.plist compiled as source Missing file sync exception Exclude Info.plist from build phase membership
Watch build fails with wrong device TARGETED_DEVICE_FAMILY not 4 Check build settings for watch targets
