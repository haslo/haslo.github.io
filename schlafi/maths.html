📐 Activity Count Computation

The first step in sleep analysis: converting raw 50 Hz accelerometer data from CMSensorRecorder into per-epoch activity counts that the classification algorithms consume. See the Science tab for the research basis.

Pipeline: Raw Accelerometer → Activity Count

1. Raw input: 50 Hz triaxial accelerometer (x, y, z) from CMSensorRecorder

2. Vector magnitude: VMi = √(xi² + yi² + zi²) − 1g
   (subtract gravity to isolate dynamic acceleration)

3. Band-pass filter: 0.25–3 Hz (isolate body movement frequencies)
   Removes: DC offset, high-frequency vibration noise
   Retains: body movements, position changes, breathing artifacts

4. Epoch aggregation: Sum |VMfiltered| over epoch window
   Aepoch = Σi=1..N |VMfiltered,i|
   where N = samples_per_epoch (50 Hz × epoch_seconds)
ParameterValueRationale
Sample rate50 HzCMSensorRecorder native rate
Band-pass0.25–3 HzBody movement frequency range
Epoch length30–60 s30s standard; 60s for phone (noisier signal)
Epoch Length Trade-off

30 seconds is the clinical actigraphy standard (matches PSG scoring epochs). 60 seconds averages out more noise, better for phone-on-mattress where the signal-to-noise ratio is lower. Schlafi defaults to 60-second epochs for phone tracking and 30-second epochs when watch data is available (cleaner signal).

B3: Algorithm Selection Rationale

Classic ≥ Modern

The 2023 Nature Digital Medicine review ("40 years of actigraphy") found that classic regression-based algorithms (Sadeh, Cole-Kripke) perform as well as modern machine learning approaches for sleep/wake classification. More complex models don't improve accuracy when the input signal is limited to acceleration.

Sadeh — Better for Younger Populations
Originally validated on children and young adults. The NATS variable (epochs with moderate activity) captures the restlessness patterns more common in younger sleepers. Higher specificity (wake detection).
Cole-Kripke — Better for Adults
Validated on adults aged 35–65. The wider window (−4 to +2 epochs) captures longer-scale movement patterns. Higher sensitivity (sleep detection). Slightly better overall accuracy.
Phone Adaptation

Both algorithms were designed for wrist actigraphy. For phone-on-mattress:

  • Relative thresholds instead of absolute — normalize activity counts to session percentile rather than using fixed cutoffs
  • Mattress-specific calibration during first 30 minutes — establish noise floor and dynamic range
  • Wider epoch windows (60s default) to average out mattress vibration noise

🌌 Sleep Stage Classification (Phone-Based)

Schlafi classifies sleep into 4 stages from phone accelerometer, following the approach used by apps like Pillow. The method is heuristic, not clinically validated, but provides useful approximations of sleep architecture.

C1: Movement Intensity Classification

Per-Epoch Movement Levels

For each epoch (30–60s), classify movement intensity into 4 levels:
LevelConditionCandidate Stage
StillAepoch < TlowDeep or REM
Micro-movementTlow ≤ Aepoch < TmidREM (periodic twitches)
RestlessTmid ≤ Aepoch < ThighLight sleep
ActiveAepoch ≥ ThighAwake
Thresholds calibrated per-session from first 30 minutes of detected sleep:
  Tlow   = P10(activity counts during sleep)  —  10th percentile
  Tmid   = P40(activity counts during sleep)  —  40th percentile
  Thigh = P75(activity counts during sleep)  —  75th percentile

C2: Ultradian Cycle Model

~90-Minute Sleep Cycle Structure

Sleep follows approximately 90-minute ultradian cycles (Rechtschaffen & Kales; Carskadon & Dement). Each cycle progresses: Light → Deep → Light → REM.

Segment night into 90-minute cycles starting from sleep onset:
  cycle_number = floor((t − sleep_onset) / 90 min) + 1
  cycle_position = ((t − sleep_onset) mod 90 min) / 90 min  —  [0, 1)

Structural priors vary by cycle:
  Cycles 1–2:   P(deep | still) = 0.40,   P(REM | still) = 0.15
  Cycles 3+:    P(deep | still) = 0.15,   P(REM | still/micro) = 0.40

Within-cycle position bias:
  First third (0.0–0.33): deep bias × 1.3
  Last third (0.67–1.0):  REM bias × 1.3

Worked Example

Sleep onset: 23:00  |  Current epoch: 01:15 (2h 15m into sleep)

cycle_number = floor(135 / 90) + 1 = 2
cycle_position = (135 mod 90) / 90 = 45/90 = 0.50  (middle third)

Epoch is "still" (Aepoch < Tlow):
  Cycle 2 prior: P(deep | still) = 0.40, P(REM | still) = 0.15
  Middle third: no position bias applied
  → Classify as Deep sleep (highest probability)

C3: Stage Assignment Algorithm

Per-Epoch Decision Process

For each epoch classified as "sleep" by Sadeh/Cole-Kripke:

  1. Determine movement intensity level (Still/Micro/Restless/Active)
  2. Determine cycle position (cycle number, position within cycle)
  3. Compute stage probabilities:
     P(stage) = movement_prior(level, stage) × cycle_prior(cycle, stage) × position_bias
  4. Assign: stage = argmax P(stage)
  5. Post-processing: enforce 5-minute minimum bout duration
     (merge fragments shorter than 5 min into surrounding stage)

C4: Confidence Scoring

Per-Epoch Confidence

confidenceepoch = P(assigned_stage) − P(second_best_stage)

Range: [0, 1] where higher = more decisive classification

Lower confidence when:
  • Mattress noise is high (calibration SNR < 3)
  • Epoch is near a stage boundary (probabilities within 10%)
  • Cycle length is unusual (<70 min or >120 min)
  • Movement level is ambiguous (near threshold boundary)

Aggregate Night Confidence

Cnight = mean(confidenceepoch for all sleep epochs)

Displayed in the UI as a data quality indicator. Low Cnight suggests the stage breakdown should be taken with a grain of salt — the sleep/wake detection is still reliable, but stage granularity is uncertain.

⭐ Sleep Quality Scoring

Reuses the existing OmniWidget SleepQualityService approach. Quality is a function of duration and phase distribution.

0–100
Quality Score

Base Score (Duration)

base = min(100, total_sleep_hours / 8 × 100)

8 hours = 100% base. Less than 8 hours scales linearly. More than 8 hours doesn't add bonus.

Phase Penalties

Each sleep phase has a healthy target range. Deviation from the range incurs a penalty.

PhaseHealthy RangeMax Penalty
Awake0–15% of total−15 pts
REM12–30% of total−15 pts
Light30–60% of total−10 pts
Deep8–35% of total−15 pts
For each phase p:
  fractionp = phase_durationp / total_sleep
  if fractionp < range_lowp:
    penaltyp = max_penaltyp × (range_lowp − fractionp) / range_lowp
  if fractionp > range_highp:
    penaltyp = max_penaltyp × (fractionp − range_highp) / (1 − range_highp)

quality = max(0, base − Σ penaltyp)
Phone vs Watch Confidence

Phone-only: Uses estimated stages from the heuristic classifier. Lower confidence is reflected in penalty attenuation — penalties are multiplied by Cnight (aggregate confidence). If confidence is low (e.g., 0.4), penalties are reduced by 60%. This prevents confident-sounding quality scores when the underlying stage data is uncertain.

Watch data available: Uses HealthKit sleep stages directly (written by Apple Watch or other validated wearables). Full penalties applied — the stage data is trustworthy.

🔍 Signal Processing for Phone-on-Mattress

Noise Floor & Signal Characteristics

Phone-on-mattress signal is approximately 9× weaker than wrist actigraphy.

Noise sources:
  • Mattress vibration dampening (material-dependent)
  • Environmental vibration (traffic, appliances, partners)
  • Phone sensor noise floor (varies by device)

Signal-to-noise ratio (SNR):
  • Spring mattress: SNR ~ 8–12 (good)
  • Latex mattress: SNR ~ 5–8 (adequate)
  • Memory foam: SNR ~ 3–5 (marginal but usable)

Band-Pass Filter Parameters

ParameterValuePurpose
High-pass cutoff0.25 HzRemove DC offset and slow drift
Low-pass cutoff3 HzRemove high-frequency vibration noise
Filter type4th order ButterworthFlat passband, reasonable rolloff
ImplementationvDSP biquad cascadeEfficient on-device processing

Relative Measurement Approach

Within-session normalization (not absolute thresholds):

  Anormalized = (Aepoch − Amin) / (Amax − Amin)

where Amin and Amax are the 5th and 95th percentiles
of activity counts from the calibration window.

First-Night Calibration

First 30 minutes of detected sleep:
  1. Establish personal noise floor (Amin)
  2. Establish dynamic range (Amax − Amin)
  3. Compute movement intensity thresholds (Tlow, Tmid, Thigh)
  4. Estimate mattress quality (SNR) for confidence scoring
