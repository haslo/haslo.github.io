Key Insight

Schlafi combines two ML approaches depending on available hardware. With Apple Watch: sensor fusion of ML-derived sleep stages, respiratory rate, HR, HRV, and SpO2 produces ~75% 4-stage accuracy with FDA-level apnea screening. Phone adds SoundAnalysis-powered snoring and breathing detection that watch can't provide. Without watch: phone accelerometer (classical algorithms) + SoundAnalysis still produces functional sleep tracking. The combination of both covers more ground than either alone.

SoundAnalysis Built-In Classifier

Apple's SNClassifySoundRequest(.version1) recognizes 300+ sound types on-device (iOS 15+). Confirmed sleep-relevant labels: snoring (index 23), breathing (index 22), cough (25), gasp (24), sigh (15), speech (0), whispering (6).

iOS 18 Background Limitation

The built-in .version1 classifier uses the GPU. iOS 18 blocks GPU work from background processes — so SNClassifySoundRequest(classifierIdentifier: .version1) fails silently in the background. For overnight audio analysis, Schlafi must use a custom CoreML model loaded via SNClassifySoundRequest(mlModel:) with MLModelConfiguration.computeUnits = .cpuOnly.

This means a custom-trained snoring/breathing model is required after all — the built-in classifier only works in the foreground. Create ML with AudioFeaturePrint transfer learning is the path: train on public audio datasets, export ~5.5 MB .mlmodel, load CPU-only for background use.

Apple Watch Sleep Staging

Apple published “Estimating Sleep Stages from Apple Watch” (updated October 2025). The algorithm uses accelerometer signals — body movements and respiration-induced wrist motion patterns — classified into 30-second epochs. Reports ~75% 4-stage accuracy, 93% sleep/wake accuracy. Interestingly, Apple's own staging is primarily accelerometer-based, not heart-rate-based — validating the core principle that movement signals carry stage information.

Apple Watch Sleep Apnea

watchOS 11 (September 2024) introduced FDA 510(k)-cleared sleep apnea notifications on Series 9/10/Ultra 2. Uses accelerometer to detect breathing disturbances via wrist micro-movements. Analyzes 30 nights before issuing notification. New HealthKit type: appleSleepingBreathingDisturbances.

Key Takeaway

Apple's built-in Watch staging (~75%) is already competitive with the best published research models (72–78%). Schlafi doesn't need to train or deploy any of these research models. They're documented here to show that the accuracy ceiling for consumer sleep staging is fundamentally ~75–78% — Schlafi is already near it by using Apple's data. Custom ML is a future option, not a v1 requirement.

Answer: Yes, but Only for Audio

Due to the iOS 18 background GPU restriction, Schlafi needs a custom CoreML snoring/breathing model for overnight use (the built-in SoundAnalysis classifier can't run in the background). Create ML with AudioFeaturePrint makes this straightforward — public datasets are sufficient. Everything else (sleep/wake, staging, watch data) uses Apple frameworks or classical algorithms with zero training.

Custom Audio Model (v1 Requirement Due to iOS 18)

Since the built-in SoundAnalysis classifier can't run in the background on iOS 18+, Schlafi needs a custom CoreML model for snoring and breathing detection. Create ML with AudioFeaturePrint transfer learning is the path: train a classifier head on public datasets (Kaggle snoring, ESC-50 negatives, PSG-Audio), producing a ~5.5 MB .mlmodel that runs CPU-only in the background. The AudioFeaturePrint feature extractor is built into iOS — only the lightweight classifier head ships with the app.

Future Options (Not v1)

Audio-based breathing rate extraction and apnea screening are feasible with public data but are not v1 features. These would use the same Create ML pipeline.

Classical Algorithms
Sadeh (1994) and Cole-Kripke (1992) for phone sleep/wake. Heuristic staging from movement + cycle priors. Quality scoring formula. No ML, 40 years of validation.

Snoring and breathing classifier trained via Create ML with AudioFeaturePrint. ~5.5 MB model, CPU-only inference in background. Required because built-in SoundAnalysis classifier can't run in background on iOS 18+.
