>_ Technical Architecture

Pipi is a standalone Xcode project within the Gwen Widgets ecosystem, sharing the HealthWidgetsCore SPM package with OmniWidget (the proof-of-concept playground).

// Architecture

// Shared Infrastructure

Reused from OmniWidget

  • Models: WaterData, ActivityHourlyData
  • Services: HealthKitService.fetchWaterEntries(), ActivityHourlyDataService (.water metric)
  • Views: ActivityChartView for cumulative water charts
  • Cache: CacheStorage + HealthKitCacheService with versioning (CacheConfiguration.cacheVersion)
  • Theme: WidgetTheme colors, WidgetStyles modifiers (e.g. .overlayShadow())
  • Charts: CustomTimeAxisView, LabelLayoutService, CustomXAxisWithCenteredLabels

New for Pipi

  • PipiEntry — nonisolated struct, timestamp + urgency enum
  • PipiDataService — actor, App Group persistence (JSON)
  • HydrationScoreService — composite score from water + pee correlation
  • LogWaterIntent / LogPipiIntent — AppIntent for interactive widgets
  • PatternDetectionService — actor, tiered pattern detection (day-of-week → k-means clustering), Accelerate/vDSP
  • AppDataStorage — persistent storage (no auto-invalidation) for source-of-truth data (pee logs, pattern profiles, trial start)
  • ControlWidget targets — iOS 18 Control Center
  • WatchKit app + WidgetFamily.accessoryCircular complications
  • RelevanceConfiguration — watchOS 26 Smart Stack contextual relevance for hydration status (@available-gated)
  • StoreKit 2 — Product, Transaction, one-time purchase

// Deployment Targets

Minimum Targets

iOS 18 / watchOS 11

Broadest user base supporting all required features: ControlWidget (iOS 18+), interactive widgets (iOS 17+), StoreKit 2 (iOS 15+).

Enhanced Experience

iOS 26+ gets Liquid Glass rendering automatically.

watchOS 26+ enables RelevanceConfiguration — Smart Stack contextual relevance for hydration status.

Both gated with @available, no user base limitation.

// HealthKit

Read + Write: HKQuantityType(.dietaryWater) — bidirectional sync with other apps. No other HealthKit types needed. Pee data is app-local only (HealthKit has no urination category — only HKCategoryType(.bladderIncontinence) which is medical/symptom, not what we want).
